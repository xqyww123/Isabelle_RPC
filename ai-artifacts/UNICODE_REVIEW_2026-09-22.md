## Proposals to the author

### Fix §1b: make our fold of two adjacent markers agree with Isabelle (recommended: yes)

- **Constraint:** "§1b (our fold of two adjacent markers differs from Isabelle's) is recorded, not fixed", together with §6 item 3's acceptance that `pretty_unicode`'s output is byte-identical before and after.
- **Relaxation:** Let the fold pattern be a marker followed by a non-marker — `_FOLD = re.compile(f"[{markers}][^{markers}]")`, with the marker set derived from `SUBSUP_TRANS_TABLE` and escaped — instead of `⇩.|⇧.|❙.`; and restate the byte-identity condition as "byte-identical except where two fold markers are adjacent, where the rendering now follows Isabelle".
- **Gain:** The pattern stops encoding a parity artefact of non-overlapping `re.sub` and starts encoding the prover's own rule (Pure/General/symbol.scala's control handling, quoted in the plan from html.scala:239: a new marker displaces the pending one, which is emitted literally). I verified the effect: `x\<^sub>\<^sub>1` renders 'x⇩⇩1' today and 'x⇩₁' after, which is what Isabelle does; the ⇧ and ❙ crossings likewise. A permanently recorded divergence from the prover disappears instead of being carried forever; a hand-written test expectation that encodes an artefact becomes a rule; and §5's only recorded *against* for the ruled Option D goes away. Still one regex, one code path — no state machine, nothing of the rejected Option C.
- **Cost:** It is a behaviour change, so §6 item 3's byte-identity must be re-established with an exception clause rather than assumed — but the measured blast radius is zero: I scanned 3,006 .thy/.ML files of phi-system and Isabelle2025-2/src and found 0 whose rendering contains two adjacent markers; the defender widened that to 14,500 sources and 9,913 checked-in .unicode.thy mirrors, also 0. One seeded expectation changes (test_unicode.py:125), and §1b's first half is rewritten as fixed while its closing paragraph — jEdit's `font:` rule and is_controllable, still unmodelled — stays.

### Record only the matches the replacement actually rewrote (recommended: yes)

- **Constraint:** §4 D as restated in the brief: `_render` "records `(start, end, output length)` per match", plus §4 D's interior-offset convention ("an offset strictly inside a match that changed length maps to the match's output start; an offset strictly inside a match that kept its length maps by identity").

- **Gain:** The mapper stops answering an identity question by asking a length question. Today that inference is sound only because a hand-written table happens to map every 2-character key to a 1-character value, and nothing says so anywhere; I verified the failure by adding the natural extension `SUBSUP_TRANS_TABLE["⇩q"] = "q̲"` (base letter + combining low line, the obvious way to fold the letters Unicode has no subscript for) — the operand is then reported one character to the right, silently. After the change, anyone may edit the fold table without knowing that rule. Unusually, the safer shape is also the smaller one: a clause is deleted and no field is added.
- **Cost:** Two reworded sentences in §4 D and one in §6 item 9; one mutant's quoted source line in test_unicode.py:324. Measured identical on 1,045,909 corpus lines and on all twelve seeded rendering classes. Zero observable behaviour change today.

### lens: offsets

Lens: offset-mapping correctness. I found no correctness defect in `_map_offsets` or `pretty_unicode_indexed`; all six findings are about the net around them, one latent robustness assumption, and one API footgun.

What I checked and found sound (scripts in /tmp/claude-1002/-home-qiyuan-Current-MLML/dcf9a85a-9a01-420a-9a51-ce2e8b6bec19/scratchpad/lens-offsets/, run as /home/qiyuan/Current/MLML/.venv/bin/python from /home/qiyuan/Current/MLML with ISABELLE_HOME=contrib/Isabelle2025-2; the table loads 624 entries as required):

1. `_map_offsets` line by line, against an INDEPENDENT oracle: a segment-decomposition reimplementation of the §4 D convention (build the piecewise literal/match decomposition, then answer each offset by locating its segment) rather than the incremental-shift loop. 50,000 randomised (records, offsets) pairs, deliberately including duplicate offsets (23,689 runs) because pass 2 receives them from pass 1: 0 mismatches, with 48,741 offsets strictly inside a length-changing match and 28,109 strictly inside a length-preserving one. 2. The composition at unicode.py:322.
